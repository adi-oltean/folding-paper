# E2 -- exact folds are self-witnessing

Generated by `run_e2.sh` (which runs `witness.py` and then calls `make_results.py`). Do not hand-edit: re-run `./run_e2.sh` from this directory instead.

Design: `research/E2-E3-design.md` ("E2 -- exact folds are self-witnessing"). Claim under test: `research/folding-witnesses-and-learning.md`, "Why folding is unusually well-suited to the witness side" -- for a BIJECTIVE fold, over- and under-approximation coincide on the folded variable, so the fold's inverse is a witness generator, no separate symbolic-execution engine. `eval/refanalyzer.py` and `eval/examples.py` are imported UNCHANGED; no new fact kind, no new IR opcode.

## Summary

Three E0 catalogue patterns are exact (bijective) folds: affine induction variable (#1), ZigZag bijective transport (#13), lockstep elimination (#16). For each, on the E0-supplied mutant (same fact, broken check):

1. Read the folded coordinate's failing value off the WITH-FACT abstract state at the check.
2. Invert the fold's closed form to a concrete input (affine: `i = s*j + c0`; ZigZag: `x = z/2`; lockstep: `i = (p - base)/s`).
3. Run `refanalyzer.Concrete` -- the exhaustive concrete interpreter -- on the recovered input and confirm it is reachable and genuinely violates the check.
4. Contrast: apply the identical inversion recipe to the SAME mutant's baseline (no-fact) alarm, and show it produces no witness -- the baseline interval is not exact (or the recovered candidate falls outside the program's own input domain), so the alarm is real but the "witness" it would naively yield is not.

**Result: 3/3 exact-fold witnesses confirmed by the concrete interpreter; 3/3 contrast cases show the baseline alarm yields no witness.** All findings below are quoted verbatim from `witness.py`'s own harness assertions (exit code 0 -- see `out/witness.rc`).

## Reading the tables

TABLE 1 is the WITH-FOLD side: the "fold interval matches the TRUE reachable hull" row cross-checks against `Concrete`'s own exhaustive enumeration (not asserted from the paper's closed form) that the WITH-FACT abstract interval has zero dead-band at this point -- the same finding E0's TABLE 2 made with zero discrepancy for these three patterns. Given that, the boundary value used for inversion is guaranteed reachable, and steps 2-3 confirm it mechanically rather than by appeal to the lemma.

TABLE 2 is the control: the SAME mutant, analyzed WITHOUT the fact. The verdict is still FAIL (an over-approximate alarm is cheap -- the interval is too wide, not too narrow), but the interval is not exact, so applying the same "read off the boundary, invert" recipe either lands outside the program's declared input domain (ZigZag: the baseline's wide `z` interval inverts to an `x` value the input statement never produces) or simply does not correspond to any state the concrete interpreter reaches at that point (affine IV, lockstep: the baseline interval's upper edge is not on the stride's grid of actually-visited iterations). Either way, no witness -- the point of the contrast.

## Scope

This demonstrates the mechanism on the three patterns whose fold is exact by construction (bijective/affine substitution). `folding-witnesses-and-learning.md` is explicit that inexact folds (convexification, residue partitioning) do NOT get this for free -- they need a real under-approximate engine (symbolic execution / BMC), with folding only shrinking the space that engine searches. That is out of scope here by design, not by omission.
